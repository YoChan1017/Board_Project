# React 22차 — 관리자 화면 고도화

## 목표

관리자 게시판/카테고리 관리와 게시글 관리 화면에서 대상 데이터를 더 빠르게 찾고, 페이지 크기·정렬·카테고리 조건을 조절할 수 있도록 한다. 기존 관리자 라우트 보호와 삭제 확인 동작은 유지한다.

## 변경 파일

- `front/src/pages/AdminBoardManagementPage.jsx`
  - 게시판 이름·설명 검색을 추가한다.
  - 선택한 게시판 범위의 카테고리 이름 검색을 추가한다.
  - 검색 중 결과가 없을 때 별도 빈 상태 및 초기화 동작을 제공한다.
  - 게시판/카테고리 총 개수와 검색 결과 개수를 표시한다.
  - 저장 및 삭제 중인 폼/액션 상태를 분명히 하고 피드백 알림 닫기 버튼을 추가한다.
- `front/src/pages/AdminPostManagementPage.jsx`
  - 기존 게시판별 제목/본문 검색 유지.
  - 카테고리 선택, 최신순/제목/조회/좋아요 정렬, 페이지당 10/20/50개 선택을 추가한다.
  - 필터 초기화와 필터 적용 후 빈 결과 안내를 추가한다.
  - 삭제 후 목록을 다시 읽어 삭제된 항목이 화면에 남지 않도록 한다.
- `front/src/App.css`
  - 검색 입력, 필터, 안내 상태 및 모바일 레이아웃 스타일을 추가한다. 이 파일 내용은 기존 `front/src/App.css` 맨 아래에 추가한다.

## API 제약

현재 `GET /api/boards/{boardId}/posts` API에는 `categoryId` 쿼리 파라미터가 없다. 관리자 게시글 카테고리 필터는 선택한 게시판에서 최대 100개 게시글을 읽은 뒤 클라이언트에서 필터링한다. API의 전체 일치 건수가 100개를 넘으면 화면에 제한 안내를 표시한다. 전체 데이터에서 정확한 카테고리 필터링이 필요하면 후속 백엔드 작업으로 해당 API에 선택적 `categoryId` 조건을 추가하는 것이 권장된다.

정렬은 현재 불러온 페이지 내에서 적용한다. 카테고리 필터가 활성화된 경우에는 최대 100개 조회 결과를 필터링한 후 브라우저에서 페이지를 나눈다.

## 보안과 권한

- 기존 `/admin/boards`, `/admin/posts`의 `AdminRoute` 보호를 변경하지 않는다.
- 프론트엔드 제어는 사용자 경험을 위한 것이며, 실제 쓰기 권한은 백엔드 Spring Security에서 보장되어야 한다.
- 삭제는 계속 확인 대화상자를 거치고, 요청 진행 중에는 다른 게시글 삭제 버튼을 비활성화한다.

## 점검 목록

- [ ] 게시판 검색이 이름과 설명을 대소문자 구분 없이 필터링한다.
- [ ] 선택한 게시판의 카테고리 이름 검색 및 초기화가 작동한다.
- [ ] 검색 결과가 없을 때 전체 목록 없음과 검색 일치 항목 없음이 구분된다.
- [ ] 게시글 카테고리 필터를 바꾸면 페이지가 1페이지로 돌아온다.
- [ ] 페이지 크기와 정렬을 바꾸면 결과가 일관되게 표시된다.
- [ ] 게시글 삭제 후 목록이 새로고침되고 페이지 이동이 올바르다.
- [ ] 좁은 화면에서 필터 컨트롤이 화면 밖으로 넘치지 않는다.

## 검증 범위와 한계

JSX/JavaScript 문법 파싱, CSS 중괄호 균형 및 ZIP 무결성을 확인한다. 실제 브라우저 클릭 테스트나 실제 백엔드 통합 테스트를 수행한 것은 아니다. GitHub에 커밋하거나 푸시하지 않았다.
