# React 19차 — 게시판·게시글 상태 UI 통일

## 목표

게시판 목록과 게시글 작성·상세·수정 화면의 로딩, 오류, 빈 결과, 접근 권한 안내를 같은 기준으로 제공한다. 일시적인 읽기 요청 실패에 재시도 동작을 제공하고, 권한이 없는 경우에는 실패 재시도가 아닌 명확한 안내와 안전한 이동 경로를 제공한다.

## 변경 파일

### `front/src/pages/BoardsPage.jsx`
- 기존 자체 마크업으로 표현하던 게시판 없음/로드 실패 상태와 게시글 검색 결과 없음 상태에 공통 `EmptyState` 컴포넌트를 사용한다.
- 게시판 첫 로드가 실패했을 때 빈 상태 카드 안에서도 재시도할 수 있도록 한다.
- 기존 게시판별 검색, 카테고리 필터, 정렬, 페이지 이동, API 제한 안내는 유지한다.

### `front/src/pages/PostCreatePage.jsx`
- 작성에 필요한 게시판·카테고리 로딩 중에는 공통 `LoadingState`를 사용한다.
- 최초 데이터 로드 실패 시 `ErrorMessage`로 오류를 알리고, 재시도 버튼이 실제로 데이터 요청을 다시 실행한다.
- 제목/내용 검증 오류와 저장 오류를 공통 오류 컴포넌트로 표시한다.
- 제출 중에는 폼을 `aria-busy` 상태로 표시하고 기존 입력 비활성화 및 중복 제출 방지를 유지한다.

### `front/src/pages/PostEditPage.jsx`
- 수정 화면의 로딩/오류 상태를 공통 피드백 컴포넌트로 통일한다.
- 게시글 조회 등 재시도할 수 있는 초기 로드 실패에 재시도 버튼을 추가한다.
- 현재 사용자 ID와 게시글 작성자 ID가 일치하지 않고 관리자도 아닌 경우 별도 권한 안내 화면을 표시한다.
- HTTP 403 응답은 일반적인 로드 오류와 분리해 권한 거부 상태로 안내한다. 권한 거부 상태에서는 의미 없는 재시도 버튼을 제공하지 않고 게시글(조회된 경우) 또는 게시판으로 이동할 수 있게 한다.

### `front/src/pages/PostDetailPage.jsx`
- 게시글 상세 로딩 상태에 공통 `LoadingState`를 사용한다.
- 404는 찾을 수 없는 상태로 표현하고, 네트워크 등 다른 로드 실패에는 재시도 버튼을 제공한다.
- 좋아요 상태 조회 실패에도 재시도 버튼을 추가한다. 상태 확인/요청 처리 중에는 버튼 문구를 구분하고 중복 좋아요 요청을 막는다.
- 삭제 오류를 공통 오류 컴포넌트로 표시한다.

### `front/src/App.css`
- 신규 공통 상태 카드 및 작은 화면 버튼 배열 스타일을 제공한다.

## 점검표

- [ ] 게시판 API 실패 상태에서 다시 시도하면 목록 로드를 다시 실행한다.
- [ ] 게시판에 게시글이 없거나 검색 결과가 없는 상태가 중앙 정렬된 공통 빈 상태로 표시된다.
- [ ] 새 게시글 작성 화면의 초기 데이터 로드가 실패했을 때 재시도가 작동한다.
- [ ] 게시글 상세 화면에서 일시적인 조회 실패의 재시도가 작동한다.
- [ ] 존재하지 않는 게시글은 찾을 수 없다는 안내와 게시판 이동 링크를 표시한다.
- [ ] 게시글 수정 권한이 없는 사용자는 수정 폼을 보지 못하고 명확한 권한 안내를 본다.
- [ ] 좋아요 상태 조회에 실패했을 때 다시 확인 버튼이 요청을 재실행한다.
- [ ] 등록·수정·삭제·좋아요 요청 중 버튼이 중복 실행되지 않고 처리 중 문구가 표시된다.
- [ ] 모바일 화면에서 상태 안내와 이동 버튼이 가로로 넘치지 않는다.

## 범위와 한계

- 이번 차수는 프론트엔드만 수정한다. API 및 DB 스키마 변경은 없다.
- 브라우저에서 실제 클릭 시나리오를 실행하거나 실시간 백엔드와 연동해 테스트한 것은 아니다.
- 프론트엔드의 권한 안내는 화면 동작과 사용자 경험을 위한 것이며, 실제 리소스 권한은 반드시 백엔드 API에서 검증되어야 한다.
- 게시글 상세 API에서 모든 권한 오류와 리소스 없음 응답의 구분 방식은 서버 응답에 따라 달라질 수 있다. 현재는 HTTP 404 및 403 상태 코드가 명시된 경우를 구분한다.
