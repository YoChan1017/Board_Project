# React 20차 — 게시글 작성·수정 경험 개선

## 목표

게시글 작성과 수정 중 잘못된 입력을 필드별로 안내하고, 실수로 새로고침하거나 요청이 실패해도 현재 탭에서 작업하던 내용을 복원할 수 있게 한다. 저장/업로드가 연속으로 호출되는 상황을 방어하고, 첨부파일 목록 조회 실패 상태를 빈 목록과 구분한다.

## 변경 파일

- `front/src/pages/PostCreatePage.jsx`
  - 제목/내용의 필드별 검증과 `aria-invalid` 상태를 추가한다.
  - 검증 실패 시 첫 번째 오류 입력으로 포커스 이동.
  - 등록 요청에 `useRef` 잠금을 추가해 상태 업데이트 전의 연속 제출도 차단한다.
  - 현재 로그인 사용자와 게시판 ID 조합으로 작성 임시 저장 키를 구분한다.
  - `sessionStorage`에 입력을 자동 저장하고 같은 탭에서 화면을 다시 열면 복원한다.
  - 등록 성공 시 해당 임시 저장 데이터를 제거하며, 실패 시 입력값과 임시 저장을 유지한다.

- `front/src/pages/PostEditPage.jsx`
  - 작성 화면과 같은 필드별 검증, 첫 오류 포커스, 연속 제출 잠금.
  - 사용자와 게시글 ID 기준으로 편집 임시 저장을 분리한다.
  - 서버의 원본 게시글과 다른 미저장 변경이 있으면 복원하고, 성공 저장 시 임시 데이터를 제거한다.
  - 권한 오류 화면과 기존 재시도 흐름은 유지한다.

- `front/src/components/PostContentField.jsx`
  - 기존 본문 문자 수와 미리보기 기능을 유지하면서 필드별 오류 메시지와 `aria-invalid`/`aria-describedby`를 지원한다.
  - `error` prop은 선택 사항이므로 다른 사용처와의 호환성을 유지한다.

- `front/src/utils/postDraftStorage.js` (신규)
  - 사용자/화면/리소스 ID가 분리된 버전형 키로 임시 저장을 관리한다.
  - 저장소 비활성화나 용량 초과가 입력/제출을 막지 않도록 예외를 처리한다.

- `front/src/components/AttachmentsSection.jsx`
  - 첨부파일 목록 조회 실패를 '첨부파일 없음' 상태와 구분한다.
  - 조회 실패 후 재시도 버튼을 제공한다.
  - `useRef` 잠금으로 연속 업로드 제출을 방어하고, 기존의 실패 파일 유지/재업로드 동작은 보존한다.

- `front/src/App.css`
  - 필드 검증 오류, 임시 저장 상태, 모바일 폼 버튼 레이아웃을 위한 추가 스타일.

## 임시 저장 동작과 개인정보

- 임시 저장은 브라우저의 `sessionStorage`를 사용하므로 현재 탭 세션에 한정된다. 브라우저 탭이 닫히면 브라우저 동작에 따라 데이터가 사라진다.
- 키에는 사용자 식별자와 게시판/게시글 ID가 포함되어 서로 다른 계정이나 게시글의 임시 내용이 섞이지 않게 한다.
- 작성 내용은 해당 브라우저 세션에 평문 JSON으로 저장되므로 공용 PC에서는 로그아웃 후 탭을 닫는 것이 좋다.
- 저장소가 차단되거나 용량이 부족하면 저장 상태 안내를 표시하지만, 입력과 서버 제출은 계속 가능하다.
- 게시글 생성/수정 API가 성공하면 관련 임시 저장 데이터를 삭제한다. 서버 요청이 실패하면 폼 값은 유지된다.

## 첨부파일 흐름

현재 첨부파일은 게시글이 생성된 다음 게시글 상세 화면에서 업로드한다. 작성 폼에 파일을 임시로 저장하거나 게시글 작성 API와 파일 업로드를 하나의 원자적 트랜잭션으로 처리하지 않는다. 업로드 파일별 오류가 발생하면 해당 파일을 선택 큐에 유지해 재시도할 수 있다. 여러 파일 업로드 중 일부가 성공했다면 성공 파일은 큐에서 빠지고 실패 파일만 남는다.

## 점검 목록

- [ ] 공백만 입력한 제목/내용 제출 시 해당 필드 오류와 포커스 이동을 확인한다.
- [ ] 제목 200자 제한과 문자 수를 확인한다.
- [ ] 새 게시글 작성 중 새로고침 후 현재 탭에서 임시 내용이 복원되는지 확인한다.
- [ ] 편집 화면에서 수정 후 새로고침 시 임시 변경이 복원되는지 확인한다.
- [ ] 서버 제출 실패 후 입력값이 유지되고 다시 제출할 수 있는지 확인한다.
- [ ] 성공 저장 후 이전 임시 내용이 다음 진입 때 다시 나타나지 않는지 확인한다.
- [ ] 빠른 연속 클릭/Enter 입력에도 중복 생성/수정/업로드 요청이 방지되는지 확인한다.
- [ ] 첨부파일 목록 API 실패 시 빈 목록으로 오인하지 않고 다시 불러오기 버튼이 표시되는지 확인한다.
- [ ] 다중 파일 업로드에서 부분 실패 시 실패 파일만 큐에 남는지 확인한다.

## 검증 범위와 한계

JSX 파싱, CSS 괄호/주석 기본 구조, 임시 저장 유틸리티의 기본 동작, ZIP 무결성을 검사한다. 실제 브라우저/서버를 실행한 통합 테스트는 별도 검증이 필요하다. 임시 저장은 동일 브라우저 탭 세션에서만 제공되며 서버 간 동기화 기능은 아니다.
