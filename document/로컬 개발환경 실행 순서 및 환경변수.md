# 로컬 개발환경 실행 순서 및 환경변수

MariaDB, Spring Boot 백엔드(STS), React 프론트엔드(VS Code)를 로컬 PC에서 실행하는 절차를 정리한다. Windows 개발환경을 기준으로 작성했다.

## 1. 실행 순서 요약

다음 순서로 실행한다.

1. **MariaDB** 서비스를 시작하고 `board_db` 데이터베이스가 있는지 확인한다.
2. **STS(Spring Tool Suite)** 에서 `back` Spring Boot 애플리케이션을 실행한다.
3. **VS Code** 에서 `front`의 Vite 개발 서버를 실행한다.
4. 브라우저에서 VS Code 터미널에 표시된 Vite 주소로 접속한다.

프론트엔드 개발 서버는 `/api` 요청을 `http://localhost:8080`으로 프록시하므로 백엔드가 먼저 실행 중이어야 한다.

## 2. 사전 준비

- JDK 21
- Spring Tool Suite (STS)
- Node.js 및 npm
- Visual Studio Code
- MariaDB Server 및 SQL 클라이언트
- Git으로 내려받은 `Board_Project` 저장소

## 3. MariaDB 실행 및 데이터베이스 준비

### 3.1 MariaDB 서비스 시작

Windows의 **서비스(Services)** 앱에서 MariaDB 서비스가 실행 중인지 확인한다. 서비스 이름은 설치 환경에 따라 다를 수 있다. PowerShell에서 확인하려면 다음 명령을 사용한다.

```powershell
Get-Service *Maria*
```

서비스가 중지되어 있다면 관리자 권한 PowerShell에서 실제로 표시된 서비스 이름을 사용해 시작한다.

```powershell
Start-Service -Name "실제_MariaDB_서비스_이름"
```

### 3.2 데이터베이스 생성

MariaDB 클라이언트 또는 GUI 클라이언트에서 관리자 계정으로 접속한 뒤 실행한다.

```sql
CREATE DATABASE IF NOT EXISTS board_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
```

현재 백엔드 기본 설정은 `board_db`를 사용하며, 기본 DB 계정명은 `root`다. 실제 비밀번호와 계정은 본인 PC의 MariaDB 설정에 맞춘다. 가능하면 로컬 개발에서도 `root` 대신 프로젝트용 계정을 사용하고, 해당 계정에 `board_db`에 대한 필요한 권한을 부여한다.

### 3.3 기존 DB의 V8 마이그레이션 확인

이 프로젝트는 Flyway로 스키마를 관리한다. `back/src/main/resources/db/migration/V8__add_user_token_version.sql`은 다음 컬럼을 `users` 테이블에 추가한다.

```sql
ALTER TABLE users
    ADD COLUMN token_version INT NOT NULL DEFAULT 0;
```

- DB가 이미 V1~V7까지 적용된 상태라면 STS에서 백엔드를 시작할 때 Flyway가 V8을 적용한다.
- 새 DB라면 Flyway가 V1부터 V8까지 순서대로 적용한다.
- V8 SQL을 별도로 실행하거나 기존 V1~V7 파일을 수정하지 않는다.
- `db/sql/draft_schema.sql`은 설계 참고용 최종 스키마 초안이며, Flyway로 관리되는 DB에서 재실행하지 않는다.

적용 상태를 확인하려면 다음 SQL을 사용할 수 있다.

```sql
SELECT version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;

SHOW COLUMNS FROM users LIKE 'token_version';
```

`flyway_schema_history`가 없으면 해당 데이터베이스에서 Flyway가 아직 실행되지 않았을 수 있다. 이 경우 백엔드의 `DB_NAME`이 의도한 DB를 가리키는지 먼저 확인한다.

## 4. 환경변수 템플릿

백엔드는 아래 환경변수를 사용한다.

| 변수 | 필수 여부 | 기본값 | 설명 |
|---|---|---|---|
| `DB_HOST` | 선택 | `localhost` | MariaDB 호스트 |
| `DB_PORT` | 선택 | `3306` | MariaDB 포트 |
| `DB_NAME` | 선택 | `board_db` | 데이터베이스 이름 |
| `DB_USERNAME` | 선택 | `root` | 데이터베이스 사용자 |
| `DB_PASSWORD` | 필수 | 없음 | MariaDB 계정 비밀번호 |
| `JWT_SECRET` | 필수 | 없음 | Base64로 인코딩된 JWT 서명 키 |
| `JWT_EXPIRATION_MS` | 선택 | `3600000` | JWT 유효 시간(밀리초), 기본 1시간 |

문서용 템플릿은 다음과 같다. 아래의 비밀번호와 키 자리는 실제 로컬 값으로 교체한다.

```text
DB_HOST=localhost
DB_PORT=3306
DB_NAME=board_db
DB_USERNAME=root
DB_PASSWORD=<로컬 MariaDB 비밀번호>
JWT_SECRET=<Base64로 인코딩한 충분히 긴 임의 키>
JWT_EXPIRATION_MS=3600000
```

**중요:** 이 프로젝트가 현재 사용하는 Spring 설정은 OS 환경변수를 읽는다. 위 내용을 `.env`라는 파일에 적는 것만으로는 자동 적용되지 않는다. STS 실행 구성의 Environment 탭 또는 PowerShell 세션에 값을 설정한다. 실제 비밀번호와 JWT 키는 Git에 커밋하지 않는다.

### 4.1 JWT 키 생성

OpenSSL이 설치되어 있다면 PowerShell 또는 터미널에서 다음 명령으로 Base64 키를 생성할 수 있다.

```bash
openssl rand -base64 32
```

출력된 값을 `JWT_SECRET`에 설정한다. 코드가 Base64 디코딩 결과를 HMAC 키로 사용하므로 임의의 짧은 문구를 그대로 넣지 않는다.

## 5. STS에서 백엔드 실행

### 5.1 프로젝트 가져오기

1. STS를 실행한다.
2. `File > Import > Maven > Existing Maven Projects`를 선택한다.
3. 저장소의 `back` 폴더를 Root Directory로 선택한다.
4. 프로젝트 가져오기를 완료하고 Maven 의존성 처리가 끝날 때까지 기다린다.

이미 가져온 프로젝트라면 이 단계는 건너뛴다.

### 5.2 실행 구성에 환경변수 입력

1. `Run > Run Configurations...`를 연다.
2. `Spring Boot App`에서 프로젝트의 실행 구성을 선택한다. 없다면 새 구성을 만든다.
3. **Environment** 탭에서 아래 변수를 추가한다.

```text
DB_HOST=localhost
DB_PORT=3306
DB_NAME=board_db
DB_USERNAME=root
DB_PASSWORD=<로컬 MariaDB 비밀번호>
JWT_SECRET=<Base64 JWT 키>
JWT_EXPIRATION_MS=3600000
```

4. `Apply`를 누르고 `Run`을 실행한다.
5. 콘솔에서 애플리케이션이 `http://localhost:8080` 포트로 정상 기동하는지 확인한다.

PowerShell에서 설정한 환경변수는 STS GUI로 실행한 프로세스에 자동으로 전달된다고 가정하지 않는다. STS에서 실행할 때는 위 Run Configuration에도 별도로 입력한다.

### 5.3 기동 후 확인

- MariaDB 연결에 성공했는지 확인한다.
- Flyway 마이그레이션이 오류 없이 완료되는지 확인한다.
- 기존 DB라면 `flyway_schema_history`에 V8이 기록되었는지 확인한다.
- 포트 `8080`을 다른 프로세스가 사용하고 있지 않은지 확인한다.

## 6. VS Code에서 프론트엔드 실행

백엔드가 정상적으로 실행된 상태에서 VS Code를 연다.

1. `File > Open Folder...`에서 저장소의 `front` 폴더를 연다. 또는 저장소 루트를 열어도 된다.
2. VS Code 터미널을 연다.
3. 저장소 루트를 열었다면 `front` 폴더로 이동한다.

```powershell
cd front
npm ci
npm run dev
```

`npm ci`는 처음 설정하거나 `package-lock.json`이 변경되었을 때 실행하면 된다. Vite가 출력하는 Local URL(일반적으로 `http://localhost:5173`)을 브라우저에서 연다.

`front/vite.config.js`에는 다음 프록시가 설정되어 있다.

```text
/api/*  ->  http://localhost:8080/api/*
```

따라서 개발 중 API 요청을 사용하려면 STS 백엔드가 실행 중이어야 한다. 프론트엔드 실행 터미널은 `Ctrl+C`로 종료한다.

## 7. 매번 실행할 때의 체크리스트

- [ ] MariaDB 서비스 실행
- [ ] `board_db`가 존재하고 접속 가능한지 확인
- [ ] STS 실행 구성에 `DB_PASSWORD`, `JWT_SECRET` 등 환경변수 설정
- [ ] STS에서 백엔드 실행 및 Flyway 로그 확인
- [ ] VS Code 터미널에서 `cd front` 후 `npm run dev`
- [ ] Vite가 출력한 주소를 브라우저에서 열기
- [ ] 화면에서 API 요청이 정상 동작하는지 확인

## 8. 종료 순서

1. VS Code 터미널의 Vite 개발 서버에서 `Ctrl+C`
2. STS에서 Spring Boot 프로세스 중지
3. 다른 애플리케이션에서 사용하지 않는다면 MariaDB 서비스를 중지해도 된다. 로컬 개발 때마다 반드시 중지할 필요는 없다.

## 9. 문제 발생 시 빠른 확인

| 증상 | 확인할 항목 |
|---|---|
| 백엔드가 DB에 접속하지 못함 | MariaDB 실행 상태, `DB_HOST`, `DB_PORT`, `DB_NAME`, 계정 및 비밀번호 |
| `JWT_SECRET` 관련 시작 오류 | Base64 키 설정 여부, 키의 공백·따옴표 포함 여부 |
| Flyway가 V8을 적용하지 않음 | STS가 연결한 DB가 맞는지, `flyway_schema_history`의 적용 버전 확인 |
| `token_version` 중복 컬럼 오류 | V8 SQL을 수동 실행했는지 확인하고 Flyway 이력과 실제 스키마를 대조. V8 SQL을 반복 실행하지 않음 |
| 브라우저 API 요청 실패 | STS 백엔드가 `localhost:8080`에서 실행 중인지, Vite 프록시 설정 확인 |
| Vite 개발 서버 시작 실패 | 포트 사용 여부, `npm ci` 실행 여부, Node.js/npm 설치 상태 |

이 문서는 로컬 개발 환경 실행 안내다. 운영 배포 시에는 별도의 계정 권한, 비밀정보 관리, HTTPS, 파일 저장 및 백업 정책을 설정해야 한다.
