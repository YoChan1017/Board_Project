# Board_Project 프론트엔드 5차 작업: 첨부파일

## 작업 내용

- 게시글 상세 화면에서 첨부파일 목록 조회
- 로그인한 게시글 작성자/관리자에게 파일 업로드 및 삭제 UI 노출
- 첨부파일 다운로드를 Axios Blob 요청으로 처리하여 기존 Bearer 토큰 사용
- 여러 파일을 선택해 순차 업로드
- 파일당 10MB 제한을 브라우저에서 먼저 검사 (백엔드에서도 제한함)
- 업로드, 다운로드, 삭제 오류 표시

## 저장소의 백엔드 API와 일치하는 경로

- `GET /api/posts/{postId}/attachments`
- `POST /api/posts/{postId}/attachments` — multipart field `file`
- `GET /api/attachments/{attachmentId}/download`
- `DELETE /api/attachments/{attachmentId}`

백엔드는 파일당 10MB 제한을 두고, 첨부파일 업로드/삭제는 게시글 작성자 또는 ADMIN으로 제한합니다. UI의 권한 숨김은 사용성 목적이며 실제 접근 제어는 백엔드에서 수행됩니다.

## 사용 흐름

첨부파일은 게시글 ID가 있어야 업로드할 수 있으므로, 새 게시글을 먼저 등록합니다. 등록 후 이동하는 상세 화면에서 게시글 작성자(또는 관리자)가 파일을 추가하면 됩니다.

## 확인 체크리스트

- [ ] 상세 화면에서 첨부파일 목록이 표시된다.
- [ ] 게시글 작성자로 로그인한 뒤 파일 하나를 업로드할 수 있다.
- [ ] 여러 파일을 선택했을 때 순서대로 업로드된다.
- [ ] 10MB 초과 파일은 업로드를 시도하지 않고 오류가 표시된다.
- [ ] 다운로드 버튼이 파일 원래 이름으로 파일을 저장한다.
- [ ] 작성자/관리자에게만 삭제 버튼이 보인다.
- [ ] 다른 사용자가 업로드/삭제 API를 직접 호출해도 백엔드가 권한을 검증한다.

## 참고/제한

- 첨부파일 업로드는 게시글 등록 후 상세 화면에서 수행하는 방식입니다. 기존 API도 게시글 ID를 경로에 요구합니다.
- 프론트엔드의 파일 크기 검사는 사용자 경험을 위한 선행 검사입니다. 최종 검증은 백엔드에 의해 수행됩니다.
