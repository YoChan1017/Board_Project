# React 18차 — 통합 검색 고도화

## 목적

통합 검색에서 작성자와 작성일 조건으로 결과를 추가로 좁히고, 검색 범위와 표시 옵션을 URL에 보관해 검색 결과를 새로고침하거나 링크로 공유해도 같은 조건을 복원할 수 있도록 한다.

## 변경 파일

- `front/src/pages/GlobalSearchPage.jsx` (교체)
  - 작성자 닉네임 일부 일치 필터
  - 작성일 시작일·종료일 필터(양 끝 날짜 포함)
  - 시작일이 종료일보다 늦은 경우 검증 메시지 표시
  - 검색 범위, 카테고리, 정렬, 페이지 크기, 현재 페이지를 URL 쿼리로 저장
  - `q`, `board`, `category`, `sort`, `size`, `page`, `author`, `from`, `to` 쿼리 파라미터에서 화면 상태 복원
  - 검색어 변경 시 게시판 범위·작성자·날짜·정렬·페이지 크기는 보존하고, 새 검색 결과에 존재하지 않을 수 있는 카테고리 선택은 초기화
  - 결과가 필터링된 뒤 전체 결과 수와 현재 조건에 맞는 결과 수를 별도로 표시
  - 삭제된 게시판 ID를 포함한 링크에 접근하면 전체 게시판 범위로 복구
- `front/src/App.css` (추가 스타일)
  - 작성자/기간 필터 UI와 반응형 레이아웃

## URL 사용 예시

`/search?q=react&board=2&category=5&author=chan&from=2026-01-01&to=2026-12-31&sort=likes&size=20&page=1`

예시에서는 `react` 검색 결과 중 게시판 ID 2, 카테고리 ID 5, 작성자 닉네임에 `chan`이 포함되고 작성일이 2026년인 게시글을 좋아요 순으로 정렬해 두 번째 페이지부터 표시한다. 이 값은 URL 형식을 설명하기 위한 예시이며 실제 DB ID나 결과를 의미하지 않는다.

## 데이터 및 API 한계

- 작성자와 작성일 필터는 현재 브라우저에 내려온 검색 결과에 대해 수행한다.
- 현행 백엔드는 게시판별 검색 결과를 최대 100개씩 조회하므로, 한 게시판의 검색 결과가 100개를 초과하면 뒤쪽 결과가 작성자/날짜 조건에 걸려 있어도 현재 화면에서 찾을 수 없을 수 있다. 기존 경고 메시지를 유지한다.
- 작성자 필터는 `authorNickname`의 부분 문자열을 기준으로 대소문자 및 호환문자 정규화를 적용한다.
- 전체 데이터 범위에서 정확하고 효율적으로 필터링하려면 후속 백엔드 작업에서 `categoryId`, `author`, `from`, `to` 등을 검색 API 쿼리 파라미터로 지원하고 필터링된 전체 건수를 반환하는 방식이 권장된다.
- 백엔드 API 및 DB 스키마는 변경하지 않는다.

## 검증 범위

JSX 구문 파싱, CSS 중괄호 균형, 패치 ZIP 무결성을 검사한다. 이 검사는 브라우저 화면 검수, 실제 백엔드 연동 또는 자동화된 상호작용 테스트를 대신하지 않는다.
